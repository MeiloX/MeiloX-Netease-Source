# MeiloX NetEase Source

A removable NetEase Music source for MeiloX source API 2. Protocol recipes, endpoint selection, request fields, account state, and response projection live in this repository. Shared presentation, playback, local data, and multi-source lyrics remain host features.

Version 0.1.5 restores the original intelligence playback request and continues recommendations when the seed track is unavailable. It includes the artwork, comment avatar, and large Home response fixes.

The package includes the exact `p6.music.126.net` permission for Home artwork alongside its existing image hosts. NetEase can return different audio CDN hosts across tracks and sessions. Audio permissions cover the exact hosts `m7`, `m8`, `m10`, `m701`, `m704`, `m801`, and `m804` under `music.126.net`; no wildcard domains are requested.

The additional audio hosts are supported by [original API response records](https://github.com/Binaryify/NeteaseCloudMusicApi/issues/1792), [Listen1's recorded player response](https://github.com/listen1/listen1_desktop/issues/797), and [MusicBot-Go's explicit CDN handling](https://github.com/liuran001/MusicBot-Go/blob/main/bot/download/service.go#L75). This is a finite reviewed list, not an enumeration of every future service host. A new host requires a reviewed package update; the source preserves the server-provided hostname.

## Build

Node.js 20 or newer and Python 3 are sufficient. No package dependencies or Gradle build are needed.

```sh
npm test
npm run package
```

Import `netease.meisource` from MeiloX source management. The package contains `manifest.json`, `index.js`, `LICENSE`, and `NOTICE`. `src/` is the editable implementation; `index.js` and the manifest are generated by `build.mjs`.

## Account configuration

Use the source account page to sign in with a browser, a Music QR code, a mobile password, or a mobile SMS challenge. A host supporting the declared interactive effects is required. Mobile challenges, captcha, outgoing SMS composition, device registration, and PC authorization remain separate verified steps. Cancelling a step never produces a successful login.

Manual configuration also accepts either the complete Cookie header from your own signed-in NetEase Music browser session or only the value of its `MUSIC_U` cookie. Select `web` for a browser session and `mobile` for a mobile session. `MUSIC_A` alone is an anonymous session. Device and URS fields are advanced migration fields; ordinary sign-in initializes private source identity automatically.

The manifest tracks authenticated identity through `sessionKeys: ['cookie', 'sessionType']` and `sessionCookieNames: {cookie: ['MUSIC_U']}`. CSRF, tracking, anonymous cookie rotation, and first profile-cache writes do not switch account ownership.

Saved source session state takes precedence over the initial configuration. Logout stores an explicit empty cookie, so an old configured token cannot silently sign in again. Account secrets stay in source-private encrypted host storage and never belong in this repository, fixtures, reports, or chat messages. Uninstalling the source leaves host tracks, downloads, queues, and lyric settings intact.

## Host contract

The host must implement the exact SDK permissions declared by the manifest: `netease.transport`, `netease.urs`, `netease.securityHeaders`, `netease.ursPuzzle`, `netease.ursCaptcha`, and `netease.history`. These are cryptographic/device primitives and guarded transport, not catalog or account repositories. Each invocation receives only this source instance's config and storage.

`netease.transport` accepts a fully shaped HTTPS request. This source supplies the final URL, Cookie, User-Agent, Android/Desktop profile headers, CSRF, EAPI `header` and `e_r` fields. Its closed `sdkConfig` contains only `{mode, signingPath?, formFields?, weapiKey?}`: `mode` is `api`, `weapi` or `eapi`; EAPI requires the explicit signing path; WEAPI requires a source-generated 16-character key; optional form fields are a flat JSON string map. The SDK only converts form data, encrypts/signs bytes, and decrypts bounded responses. It never selects endpoints, infers paths, reads accounts, or appends business/profile fields. It returns every `Set-Cookie` header. `netease.urs` accepts the plugin's own official URS URL and `{parameters, body}` frame; the host only encrypts, sends, and decrypts that frame.

Interactive work is returned as `{hostEffect, continuation}`. The host releases the sandbox before executing effects and resumes the same operation with `$continuation`. The continuation contains only an execution-specific opaque storage key and random nonce. Concurrent operations never share a pending-state key, including identical actions waiting on SDK proof or file selection. Resume validates the action namespace, key and nonce against the stored original parameters. Pending private state expires after five minutes; expired plans may be reclaimed, while active plans are never evicted. At most sixteen plans and 60 KiB of pending source storage are admitted. Host account/provider/screen ownership checks must reject stale continuations. `source.continue` is an internal, permission-free yield used by longer read chains. Every sandbox segment issues at most four HTTP requests.

`feature.invoke` accepts `{feature, action, parameters}`. The manifest lists the supported closed feature/action pairs. Existing high-level method names are retained; `online` is accepted as a compatibility family and resolves to the declared action family. Music identifiers and public social/account identifiers are strings. Remote integer tokens outside IEEE-754 precision are parsed losslessly before projection.

Most advanced results preserve the former shared UI DTO fields. Account playlists explicitly return `{playlists, hasMore, nextOffset}` in pages of at most 100; a host compatibility facade can collect up to the former 2,000-row limit without exceeding sandbox result/storage budgets. Contacts return `{contacts, hasMore, nextOffset}` and advance by raw fetched rows, including duplicates. Account connections use up to 30 raw rows per page so verified-user artist enrichment fits the bounded request budget. Cloud music, podcasts, and programs likewise retain their raw paging cursors. Typed library scans resume across sparse raw pages without returning a misleading empty filtered page.

`playback.qualities` returns `{items, nextCursor}` after up to four real playback probes. `playback.resolve` can return `{nextCursor}` to continue its remaining quality ladder. The host must finish the bounded same-source ladder before trying another source. Trial URLs are rejected; returned audio resources never contain the account Cookie.

The history SDK is a pure NCBL byte encoder: `{meta, recordBase64}` becomes `{bodyBase64}`. This source owns immutable playback-session snapshots, event fields, multipart framing, clientlog upload URL, and request headers. Mobile NCBL and weblog are attempted independently; cancellation still stops both. The host supplies bounded binary request decoding and explicit network-error responses for this optional telemetry chain. No SDK performs a hidden catalog, account, or telemetry HTTP request.

## Offline checks

Home hero sections preserve ordered source-owned cards for content navigation, declared feature routes, source-pinned radio, and typed feature queues. Square home cards retain native radar/artist cover-caption rules, separate primary/secondary titles, cover text lines, play-count details and single-line titles through neutral optional presentation fields. The source removes only service-added artwork labels where the original UI renders its own captions. The host uses its original recommendation-card component and snapping; `discovery.homePlayback` supplies complete intelligence/podcast queues. Other feed sections retain the original DSL module visibility, ordering and optional title rules.

The aggregate Node contract suite covers desktop/mobile wire profile parity, home card actions and native parser fixtures, semantic device SMS challenges, outgoing SMS refresh, artist/daily metadata, public captured catalog projection, scoped identifiers, lossless large IDs, cookie authority, read-only WEAPI fallback, ordered duplicate tracks, ownership checks, sparse library continuation, real-probe quality paging, messages, together synchronization, URS challenges, device registration, cloud upload effects, cancellation, and security summary continuation. Fixtures contain no account credentials, audio, or lyric content. Network behavior requiring an authenticated account is verified through boundary responses here; host/AVD integration is validated in the MeiloX repository.
